# Easy task（中文对照）

本文件是 [`SKILL.md`](SKILL.md) 的中文对照，供人阅读，运行时不起作用。

**一条任务结束在一次提交上——但这个 skill 在写第一行代码之前就停下。** 它只写简报，而简报就是交给实现者
的全部合同。编码由 `easy-implement` 完成，而它可能跑在比这里更便宜的模型上。

这个拆分正是重点。强模型掌握上下文、做判断，把简报写得够密，密到一个更弱的模型不用自己做任何判断就能执行。
所以这个 skill 留下的每一个未决，都是实现者将被迫去臆造的决策——而实现者恰恰是最没资格做这决策的一方。

先把整批写完，再交接。整批就是一个 phase：里面每条任务都写，下一个 phase 的一条都不碰。`easy-plan` 把每个
phase 卡在三到七条，所以是三到七份简报。整批是一道闸门：整批写完之前，任何人都不写一行代码。

一个 phase 超过七条任务，那它就是两个 phase。别去写二十五份简报：把 phase 重切，或者只取一个 phase，剩下的
留给下一批。

写之前先读 [references/readability-law.md](references/readability-law.md)，十二条在这里全部适用。

## 输出

问一次：**Markdown，还是单文件 HTML 报告？** 一批任务简报，答案几乎总是 Markdown。要报告，先把 Markdown
写完，再调用 Skill 工具并传入 "easy-report"。

## 为实现者而写

读者不是你，而且很可能不如你强。由此得出四条规矩，它们就是这个 skill 从"执行"里拆出来的原因：

- **每个决策都标出处。** `锁定在服务端（ADR 0007）`，而不是`锁定在服务端`。没有出处的决策，会被下一个读它
  的人重新纠结。
- **命令写全，不要描述。** `npm test -- src/auth`，而不是"跑一下 auth 测试"。更弱的模型绝不该去猜怎么调用。
- **每个期望值都来自独立来源**，绝不来自读代码。更弱的模型分不清同义反复的假测试和真测试，所以简报必须把真
  的那个直接递给它。
- **点名停止触发条件。** 任务可能卡住的地方，讲明白，并讲清实现者该停下来上报，而不是猜。

一份指望读者"自己琢磨"的简报，等于把最难的那部分丢给了最没本事的一方。

## 第一到第四部分：简报

一条任务一份文档，每份一屏。四部分，不许多。一份简报超过一屏，说明它背着一条本该写在代码里的事实，或者背了
第二条任务。

### 1. 这条任务站在哪里

三行：它属于哪个 phase 以及那个 phase 的目标、它推进了什么、它的前后边。写清开始前必须成立什么，以及谁在
等它。

代号照旧带着名字：`Phase 2 管理员能解锁`、`R-3 管理员手动解锁`。

### 2. 开发需要知道什么

五块，各有预算。这一部分决定任务能不能落地：写在这里的**事实**会过期，**路径**不会。

| 块 | 写什么 | 预算 |
|---|---|---|
| **先读** | 3 到 5 条，`路径 —— 它回答哪个问题` | 3–5 行 |
| **已经定下的** | 这条任务不得重开的决策，各带出处 | ≤4 行 |
| **边界与接缝** | `easy-plan` 点名的接缝、碰什么、不碰什么 | ≤3 行 |
| **怎么跑** | 这条任务的测试命令与类型检查命令 | ≤3 行 |
| **未知** | 最可能卡住的地方，以及停下来上报的触发条件 | ≤3 行 |

没有问题的路径是噪音。这些是**入口**，不是清单：给交接的人此刻会念出来的那三到五个地方，剩下的让实现者从这
些种子搜出去。

接缝是计划定的。这里只复述它，不新增：简报自己挑一条接缝，就是把计划已经关掉的决策重新打开。

### 3. 工作流

只针对这条任务的编号步骤，一步一个动作，每步说明它产出什么。五到八步正常。第一步永远是**读第二部分，并用一
句话复述这条任务**——复述才是刚才读那些文件的目的，也是实现者第一次有机会抓住一份写错的简报。

### 4. 测试用例

一张表，不写测试代码：

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 连续两次登录失败 | 用户仍然能登录 | `login()` |

期望值必须来自独立来源：一个已知正确的字面量、一个算过的例子、计划本身。重算一遍代码在做什么的期望值，是靠
构造通过的，永远不会和代码产生分歧。

五条用例通常够了。测试本身由 `easy-implement` 在后面一条一条红着写。

<task-brief>

## 1. 这条任务站在哪里

- **Phase 1 锁定真的生效**，它的目标是：被锁的用户进不来。
- **这条任务推进 R-1 三次失败后锁定 5 分钟**：让计数真正读写数据。
- **开始前**：无。**等它的是**：`解除锁定并保留计数`。

## 2. 开发需要知道什么

**先读**

- `src/auth/login.ts` —— 登录路径今天在哪里分叉，拒绝该插在哪。
- `src/auth/failedAttempts.ts` —— 阈值、计数规则，以及谁在读它们。
- `docs/adr/0007-session-storage.md` —— 会话记录为什么存在，免得锁定再抄一份。

**已经定下的**

- 锁定在服务端。客户端校验已被计划否掉。
- 计数属于用户，不属于会话。
- 阈值取常量，这一轮还不从配置读。

**边界与接缝**

- 动 `src/auth`。不碰管理端。
- 接缝：现有的 `login()` 入口，不新增。

**怎么跑**

- `npm test -- src/auth`，然后 `npm run typecheck`。

**未知**

- 两次失败会不会交错、把一次计数弄丢。如果这里做不到原子的读改写，停下来上报。

## 3. 工作流

1. 读上面三个文件，然后用一句话复述这条任务。
2. 在 `login()` 接缝上写出用例 1 的失败测试。
3. 记一次失败，到阈值时写锁定截止时间。跑测试。
4. 补用例 2 和 3，先红再绿。
5. 跑 `npm test -- src/auth`，再跑 `npm run typecheck`。
6. 提交。

## 4. 测试用例

| 用例 | 输入 | 期望 | 接缝 |
|---|---|---|---|
| 1 | 连续两次登录失败 | 用户仍然能登录 | `login()` |
| 2 | 连续三次登录失败 | 第三次返回锁定错误 | `login()` |
| 3 | 三次失败后用正确密码 | 仍然返回锁定错误 | `login()` |

## 流程

三步。每步结束在一个你能验证的判据上。

### 1. 把整批写完

一个 phase 里每条任务一份简报，用上面的模板。如果这个 phase 还没有计划，先调用 Skill 工具并传入
"easy-plan"。

**完成判据**：phase 里每条任务都有简报，且每份简报都在预算内。

### 2. 用自足性验收

不写一行代码。把每份简报当作一个没有本次对话记忆、也够不到写它的那个强模型的模型来读。一份简报要能只靠它自
己的四部分被执行——每个决策都标了出处、每条命令都写全、每个期望值都独立、每个卡点都配了停止触发——才算过。

**完成判据**：整批完成，且每份简报都过了这道冷读。

### 3. 交接

把简报交给 `easy-implement`，或者直接交给实现者模型。这个 skill 不写代码、不落提交。

**完成判据**：简报已交付，且里面没有任何东西还等着只有你才掌握的事实。

## 停下来问

出现下面任何一条，就在交接前停下来问用户：

- 这条任务需要一个计划没做的决策。
- 计划点名的接缝不存在，或者比计划说的更低。在这里改简报，比到实现当中才发现要便宜。
- 某条用例找不到独立来源的期望值。
- 这个 phase 大于七条任务，而且切不干净。

## 反模式

- 写任何代码。那是 `easy-implement` 的活，在这里开始就毁掉了拆分。
- 简报写成整段散文。要块，要行。
- "先读"清单里的路径不带问题。那是清单，不是交接。
- 决策不带出处，于是实现者把它重新打开。
- 命令只描述、不写全。
- 期望值把代码在做的事重算一遍的测试。
- 卡点被点名却没叫人停下，于是实现者猜着越过去。
- 一批少于三份或多于七份简报。
