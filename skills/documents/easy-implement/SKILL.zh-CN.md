# Easy implement（中文对照）

本文件是 [`SKILL.md`](SKILL.md) 的中文对照，供人阅读，运行时不起作用。

**一条任务结束在一次提交上。** 这一句话同时定下了任务的粒度、它的证明，和它什么时候算完。

这个 skill 消费 `easy-task` 写出的一批简报，一条一条落地。它写得很紧，一步步照着走，因为跑它的模型可能比写
简报的模型更便宜。**照简报做，别去改进它。** 思考在上游已经做完，简报就是那份思考的记录。

如果还没有一批简报，就停下来，先调用 Skill 工具并传入 "easy-task"。没有简报就实现，正是这条链要防的事。

写收口总结之前，先读 [references/readability-law.md](references/readability-law.md)。

## 简报就是合同

四条规矩，跑这个 skill 的模型越弱，它们越要绑紧：

- **不得重开"已经定下的"里的任何一条。** 那些决策是掌握上下文的那个模型做的。在这里、用更少的上下文重新定，
  正是一批活悄无声息走偏的方式。
- **不得自己造接缝。** 用简报点名的那条。那条接缝不存在，就停下。
- **不得改期望值。** 简报的期望值来自独立来源。用你自己的代码重算一个，测试就什么都证明不了。
- **当简报含糊、写错、或缺了你需要的东西时，停下来上报。** 讲清哪份简报、哪一行。别猜。这里的一次猜测，是由
  最没资格做决策的一方做出的决策。

## 循环

六步。每步结束在一个你能验证的判据上。

### 1. 确认整批

phase 里每条任务都有简报，且简报完整。如果没有，调用 Skill 工具并传入 "easy-task"。

**完成判据**：整批就在你面前，完整。

### 2. 取前沿

做那些前置已经完成的任务，一次一条。前面没有东西挡着的任务就可以开工，线性 phase 就是从前往后。

**完成判据**：选中了一条任务，并且你能说出为什么它是下一条。

### 3. 复述，并对照简报核验

读简报第二部分，用一句话复述这条任务。把复述和第一部分对照。两者对不上，说明简报教了你一件它本不想教的事
——停下来上报。

**完成判据**：复述和第一部分对得上，或者你已经上报。

### 4. 先红后绿

在简报点名的接缝上写一条失败测试，然后写刚好让它通过的最少代码。按简报列出的顺序逐条用例重复。只在那条接缝
上测，切片保持竖直：一条测试、一次实现，再做下一条。

**完成判据**：第四部分每一条用例都绿，而且这些测试读起来是行为，不是结构。

### 5. 提交

一次意图一次提交，用 conventional commit 格式。测试没过之后修好的 bug 单独占一次提交，因为下一个读日志的人
想知道当时坏在哪。

**完成判据**：工作区干净，读者从日志里能看出改了什么、为什么改。

### 6. 下一条，然后收口

取下一条前沿任务，从第二步重复。这批最后一条提交后，调用 Skill 工具并传入 "easy-summary"，产出这批的总结：
改了什么、意味着什么、还开着什么。

**完成判据**：总结文档存在，且这批里每条任务要么已提交、要么被点名说没做完。

## 提交

`type(scope): 改了什么`，祈使句，type 小写：`feat(auth): count failed logins and lock at the
threshold`。

- 一次意图一次提交。一条任务通常一次，装了两个意图就两次。
- 红线测试之后的修复单独一次，`fix(auth): ...`。测试和修复绝不共处一次提交。
- 提交正文写"读文件改变了什么"。发现就住在那儿，因为简报写完就不再编辑。

## 停下来上报

出现下面任何一条，就停下来，讲清哪份简报、哪一行，退回给写简报的人。别靠猜往下走：

- 读第二部分改变了这条任务。
- 简报点名的接缝不存在，或者比简报说的更低。
- 某条用例的期望值缺失，或经独立核对看起来不对。
- 这条任务需要一个简报没做的决策。

上报不是失败。那正是简报在干它的活：在接缝处接住强模型无法预见的那一点。

## 反模式

- 手里没有整批简报就开始写代码。
- 重开简报标了"已经定下的"的决策。
- 造一条简报没点名的接缝。
- 改期望值去迁就代码。
- 猜着越过含糊，而不是上报。
- 红线测试和它的修复共用一次提交。
- 做完最后一条任务，没有调用 `easy-summary`。
